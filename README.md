# ResumeIQ

A web-based agentic recruitment pipeline that ingests a candidate's profile, grounds a natural-language Q&A layer against verifiable facts, and runs an autonomous, multi-step evaluation workflow to dispatch a structured hiring assessment.

## System Design

ResumeIQ is built to prioritize **determinism, auditability, and hallucination resistance**. Rather than feeding a raw PDF into an LLM and hoping for the best, the system extracts the data into a typed schema and performs critical logic (like date arithmetic and red flag detection) in deterministic code *before* involving the LLM.

```mermaid
flowchart TD
    A[Mock JSON] -->|Ingestion Seam| B(parsing.py)
    B -->|Pydantic Model| C[(Candidate Object)]
    
    C -->|Pre-compute Timeline| D[qa_engine.py]
    D <-->|Grounded QA| Recruiter
    
    C -->|Extract & Timeline| E[agent_workflow.py]
    E --> F[1. Extract]
    F --> G[2. Map]
    G --> H[3. Flag]
    H --> I[4. Recommend]
    I --> J[5. Dispatch]
    
    J -->|File Export| K[output/*.json | *.pdf]
    J -->|Mock SMTP| L[Console Log]
```

The application is structured into the following key components:
1. **Mock Data Ingestion (`parsing.py`)**: Loads a realistic mock candidate resume (deliberately including grey areas like an ambiguous title and an employment gap) and validates it against a typed Pydantic schema (`models.py`). To support real PDF/OCR upload, only `load_candidate()` needs to be swapped.
2. **Natural Language Q&A (`qa_engine.py`)**: Enables a recruiter to ask questions about the candidate using a highly constrained, anti-hallucination prompt.
3. **Agentic Pipeline (`agent_workflow.py`)**: An auditable, 5-step pipeline that maps the data, flags concerns, generates a role recommendation, and dispatches the final form.
4. **FastAPI & UI**: A backend serving REST routes for Q&A and evaluation, with a lightweight, single-page HTML frontend.

## Prompt Strategy

The single most important reliability decision in this application is **separating deterministic calculations from generative inference.**

The Q&A Engine (`qa_engine.py`) employs a strict anti-hallucination strategy:
1. **Pre-computed Facts (Date Math)**: LLMs are notoriously unreliable at date arithmetic. Instead of asking the model to find gaps, `parsing.py` computes the employment timeline and gaps deterministically in Python. This timeline is then injected into the system prompt as a verified fact.
2. **Structured Context Injection**: The `Candidate` object is injected into the prompt as a structured JSON blob, not a re-narrated paragraph. This ensures the model can reference exact field names (e.g., job titles, specific dates) without paraphrasing drift.
3. **Explicit "Not Stated" Refusals**: The system prompt explicitly forbids the use of outside knowledge and requires the model to say *"This information is not stated in the resume..."* when information is missing.
4. **Few-Shot Anchoring**: A concrete example in the system prompt anchors the refusal behavior, showing exactly how the model should respond to unanswerable questions.

## Next Steps (If given another week)

1. **OCR Pipeline (`parsing.py`)**: Replace the JSON ingestion seam with `pdfplumber` or AWS Textract to parse real PDFs into the `Candidate` schema.
2. **Vector DB (Multi-Candidate)**: Move beyond a single candidate context by introducing ChromaDB or Qdrant. This would allow queries like *"Show me all candidates with Kubernetes experience who have no employment gaps."*
3. **ATS Integration (`dispatch.py`)**: Replace the mock SMTP service with API calls to Greenhouse or Lever to attach the evaluation directly to the candidate's ATS profile.
4. **Enhanced React UI**: Replace the vanilla HTML/JS frontend with a Next.js or React application utilizing WebSockets for real-time streaming of the agentic pipeline steps (so the recruiter can watch the extraction, mapping, and flagging happen in real time).

## Time Log

* **0.0 - 0.5h**: Setup, dependency planning, and modeling the Pydantic schemas (Task 1).
* **0.5 - 1.5h**: Crafting realistic mock data with intentional grey areas. Building the parser and the pre-computed timeline logic to handle gaps robustly.
* **1.5 - 2.5h**: Designing the Q&A Engine (Task 2), focusing on the anti-hallucination system prompt, few-shot examples, and the mock/Gemini/OpenAI abstraction layer.
* **2.5 - 3.5h**: Building the 5-step agentic pipeline (Task 3). Deliberately splitting extraction, mapping, and flagging into deterministic steps before doing the LLM recommendation. Building the PDF/SMTP dispatch mocks.
* **3.5 - 4.5h**: FastAPI plumbing, building the minimalist HTML frontend, and testing end-to-end to ensure output reliability and UI usability.
* **4.5 - 5.0h**: Code cleanup, test suite expansion, and writing this README.
